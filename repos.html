KeshavSoft provides two powerful transformation strategies: the Unified 3-in-1 Engine (node-json-transformer) for single-pass conversion, or the Modular Micro-Engine Pipeline (select ➔ rename ➔ map) for granular multi-stage workflows.

🏛️

Two Complementary Architectural Paradigms

Pick the best paradigm based on your pipeline complexity, observability, and performance requirements.

★ Recommended Unified Approach

1. The Unified All-in-One Engine

Use node-json-transformer to accomplish Field Selection, Key Renaming, and Schema Contract Reshaping simultaneously in a single declarative pass.

Raw Data ➔ [ node-json-transformer (Transform) ] ➔ Clean Schema ➔ [ json-to-tag-table ]
  • ✔ Single Dependency & Pass: Eliminates intermediary object allocations.
  • ✔ Automatic Pruning: Unreferenced source keys are dropped automatically.
  • ✔ Direct Renaming: Output template keys define the new naming schema.
  • ✔ Complex Collections: Handles XML dot-notated tags and nested sub-arrays cleanly.
Modular Micro-Engines

2. Modular 3-Stage Pipeline

Assemble dedicated, zero-dependency micro-tools (select-json-by-json, rename-json-keys, map-json-by-json) when you need step-by-step auditing or separate stage microservices.

Raw Data ➔ 1. Select ➔ 2. Rename ➔ 3. Map ➔ 4. Table UI
  • ✔ Zero Dependencies: Each micro-tool has 0 dependencies and tiny bundle size.
  • ✔ Single Responsibility: Each engine only does one job exceptionally well.
  • ✔ Step-by-Step Observability: Inspect output between projection and normalization.
  • ✔ Composable: Swap or omit individual steps in distributed microservices.

node-json-transformer ★ Unified 3-in-1 Engine
Published on npm as node-json-transformer • json-traversal
📂 GitHub Repository

A high-performance JSON-to-JSON transformation engine where the source JSON contains the data and the transformation JSON describes the output recipe. In a single declarative specification, it replaces the need for 3 separate stages by performing selection, key renaming, and hierarchy contract mapping in one sub-millisecond execution.

⚡ Task 1: Field Selection

Only fields declared in the output recipe are kept. Bulky internal keys, audit fields, or raw XML noise are automatically discarded without needing a prior projection step.

🏷️ Task 2: Key Renaming

Output keys in your template (e.g. customer_name, transaction_date) dictate the new property names, instantly normalizing legacy uppercase or dot-notated source keys.

🗺️ Task 3: Contract Mapping

Defines the exact shape of your downstream API contract: nested objects via item: { ... }, collection mapping via [ { list: "...", item: { ... } } ], and path extraction.

1. Raw Source Data Input JSON
2. Transformation Recipe Template JSON
3. Transformed Result Output JSON
The Mental Model: LEFT / SOURCE DATA ────▶ RIGHT / OUTPUT RECIPE.
Keys on the transformation side become keys in the output. String values on the transformation side are instructions for finding values in the source. Unmentioned source fields are automatically pruned.

🔮 node-json-transformer
Step 2: Transform

Unified declarative transformation engine. Combines field selection, property renaming, and contract schema mapping in a single pass. Designed especially for JSON derived from XML/Tally structures with dot-notated keys.

Mental Model: Source JSON contains data, Transformation JSON describes output. Selected, renamed, and reshaped simultaneously.
const { transform } = require("node-json-transformer"); const result = transform(data, { item: { customer_name: "CUSTOMER_NAME", transaction_date: "TRANSACTION_DATE" } });
📂 GitHub Repo ⚡ Live Sandbox
⚡ select-json-by-json
Step 1: Projection

High-performance, zero-dependency JSON projection engine. Traverses bulky nested structures and arrays, pruning away every field not explicitly specified in a declarative projection specification object (true = keep).

Mental Model: Input data is the source of truth. The engine mirrors the original data shape, retaining only requested properties without mutating the source tree.
selectJson(rawData, { INVOICE_NUMBER: true, DATE: true, ALL_INVENTORY_ENTRIES_LIST: { ITEM_NAME: true, TOTAL_AMOUNT: true } });
📂 GitHub Repo ⚡ Playground & Docs
🏷️ rename-json-keys
Step 2: Normalization

Recursively normalizes property names across deeply nested objects and array collections. Converts uppercase, legacy, or dot-notated XML keys into clean, developer-friendly camelCase property names.

Mental Model: Input data remains the source of truth for values and hierarchy. The mapping dictionary provides substitution rules with support for scoped $as mappings.
renameJsonKeys(projectedData, { INVOICE_NUMBER: "invoiceNo", DATE: "date", ALL_INVENTORY_ENTRIES_LIST: "items", ITEM_NAME: "name", TOTAL_AMOUNT: "amount" });
📂 GitHub Repo 🏷️ Playground & Docs
🗺️ map-json-by-json
Step 3: Contract Mapping

Template-driven declarative JSON transformation engine. Defines the exact target schema required by downstream consumers, pulling source values via dot-notation, static values, and child array mapping.

Mental Model: Target template is the source of truth. The engine instantiates the contract template and populates it using $from array extractors and dot paths.
mapJson({ invoice: "INVOICE_NUMBER", date: "TRANSACTION_DATE", lineItems: { $from: "ALL_INVENTORY_ENTRIES_LIST", product: "ITEM_NAME", total: "TOTAL_AMOUNT" } }, rawData);
📂 GitHub Repo 🗺️ Playground & Docs
📊 json-to-tag-table
Step 4: Table UI

Visual web table generator built for hierarchical and nested datasets. Inspects scalar columns and automatically converts deep sub-arrays (e.g. inventory allocations) into interactive drilldown triggers.

Mental Model: Structured table representation. Transforms flat or deep records into responsive HTML tables with modal drilldowns and custom skinning support.
const table = new Table({ theme: "default", data: cleanJson }); table.methods.render({ targetHtmlId: "tableContainer" });

🧩 json-to-tag
Compiler Engine

Zero-dependency JSON-to-DOM compiler and specification validator. Compiles serializable JSON schema specs into live native HTML DOM elements based on a strict catalog schema (tags.json).

Mental Model: Strict catalog enforcement. Ensures attribute safety, permitted nesting rules, and valid tag hierarchies before rendering into the DOM.
jsonToTag({ tag: "div", attributes: { class: "card p-3" }, children: [ { tag: "h4", text: "Dashboard Overview" } ] });
